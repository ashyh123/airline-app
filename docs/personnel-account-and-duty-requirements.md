# 人员账号、工作状态与临时调用管理需求（评审稿）

版本：0.2　日期：2026-09-24　状态：待评审

## 1. 背景与目标

当前系统已有系统管理员、调度人员、油车工作人员三种角色，登录后按账号权限进入各自工作台。代码中的账号由后端初始化时写入数据库；调度台展示车辆及其司机姓名，但没有人员名册和当班人员管理。油车工作人员目前通过账号绑定的 `vehicle_id` 查看和更新工单。

本次新增功能的目标是：管理员可登记人员并开通登录账号；调度台及时显示人员变化；调度人员可根据当天保障安排，将已登记的加油人员加入或移出可调度队伍，并区分“值班、休闲、休息”三种工作状态。账号管理、人员状态和车辆派工分别处理。

## 2. 范围与术语

- **人员账号**：由系统管理员创建的登录身份，角色为调度人员或加油人员。
- **账号状态**：账号是否允许登录，由系统管理员管理；停用不删除人员和历史记录。
- **工作状态**：加油人员当前为“值班、休闲、休息”中的一种，由调度人员维护；与账号的启用/停用状态独立。首版由人工维护状态，暂不按日历时间自动切换。
- **可调度队伍**：包含“值班”和“休闲”人员；“休息”人员不参与临时调用。加入/移出队伍改变工作状态，不创建或删除登录账号。
- **车辆绑定**：一名值班加油人员在同一时刻负责的一辆加油车。车辆和人员是不同资源；休闲、休息人员不保留有效车辆绑定。
- **实时显示**：管理端确认变更后，已打开的调度台无须手动刷新，正常网络条件下 5 秒内看到最新人员状态；网络中断后恢复时应自动补齐最新状态。

本需求不包含自助注册、排班计划自动生成、工资考勤及跨机场人员管理。

### 三种工作状态

| 状态 | 业务含义 | 临时调用 | 派工规则 |
| --- | --- | --- | --- |
| 值班 | 已到岗并负责指定车辆，可为空闲或正在执行任务 | 可以；正在作业时只能安排不冲突的后续任务 | 车辆可用、油量充足且无任务冲突时，可直接接收工单 |
| 休闲 | 在场或可及时到岗的候命人员，当前无执行任务和有效车辆绑定 | 可以；由调度员临时调用并指定车辆 | 调用确认、绑定车辆并转为“值班”后才能接收工单 |
| 休息 | 正在休息或已离班，不承担当前保障任务 | 不可以 | 不进入可选人员、智能调度和人工改派候选范围 |

账号被停用时，不论记录的工作状态是什么，均不可登录或被调用。

## 3. 角色与权限

| 功能 | 系统管理员 | 调度人员 | 加油人员 |
| --- | --- | --- | --- |
| 查看调度人员、加油人员名册 | 可以 | 可以，隐藏敏感资料 | 仅查看本人信息 |
| 创建调度人员、加油人员登录账号 | 可以 | 不可以 | 不可以 |
| 修改人员基本信息、重置密码、停用/启用账号 | 可以 | 不可以 | 不可以 |
| 调整加油人员工作状态、加入/移出可调度队伍 | 可以查看结果 | 可以操作 | 仅查看本人状态 |
| 临时调用值班/休闲人员并安排车辆 | 不负责日常操作 | 可以操作 | 仅查看本人安排 |
| 为值班加油人员指定/调整负责车辆 | 不负责日常操作 | 可以操作 | 仅查看本人车辆 |
| 查看和上报作业工单 | 维持现有权限 | 维持现有权限 | 仅本人当前负责且已分配的工单 |

所有操作都由服务端按登录账号鉴权；隐藏按钮不能代替服务端权限检查。

## 4. 功能需求

### FR-01 管理员创建人员账号

1. 管理员在“人员与账号管理”中选择角色（调度人员或加油人员），填写工号、姓名、登录账号和初始密码；联系电话为选填。工号和登录账号在系统内唯一。
2. 系统校验必填项、账号格式和密码强度；重复工号或登录账号应给出明确提示，不得生成部分人员记录。
3. 创建成功后，人员进入“启用”状态，可以使用新账号和初始密码登录。角色由创建时的记录决定，登录页不提供手动选角色。
4. 新建加油人员默认处于“休息”状态，不要求立即绑定车辆；尚未转为值班并绑定车辆的人员可以登录，但显示当前状态和“暂无可执行工单”，不能接收或上报工单。
5. 创建调度人员后，该人员登录即可进入调度工作台，其姓名出现在调度人员名册中。

### FR-02 管理员维护人员账号

1. 管理员可按角色、工号、姓名、账号、状态查询人员；列表显示创建时间、账号状态，以及加油人员的工作状态和当前车辆。
2. 管理员可修改姓名、联系电话等资料，重置初始密码，以及停用或重新启用账号。账号和工号创建后原则上不修改；确需更改时另行评审数据迁移规则。
3. 停用账号后，新的登录请求应被拒绝，已有会话应立即失效。停用加油人员前如有待执行或作业中工单，应提示并阻止直接停用，待调度人员完成交接；无活动工单时，停用同时将工作状态改为“休息”并解除车辆绑定。
4. 系统不得在人员列表、日志或接口响应中展示明文密码。密码应以安全哈希保存，初始密码仅在创建/重置时供管理员交付，首次登录须修改。

### FR-03 调度台实时展示人员

1. 调度工作台新增“人员与可调度资源”区域，展示已启用的调度人员名单，以及加油人员的姓名、工号、账号、工作状态、负责车辆、车辆状态和当前任务摘要。可按“值班、休闲、休息”筛选，并分别显示人数。
2. 管理员新增、修改、停用人员，或其他调度人员调整工作状态、临时调用和车辆绑定后，当前调度台在 5 秒内更新。界面显示最后更新时间；同步失败时给出提示并可重试。
3. 停用人员在默认可调度列表中不可选，仍可通过历史/筛选视图查看，以便追溯旧工单。

### FR-04 调度人员加入人员及临时调用

1. 调度人员从管理员已创建且处于启用状态的加油人员中调整可调度队伍；不得在此创建账号或修改密码。确认人员结束休息并可候命后，可将其由“休息”调整为“休闲”。
2. “值班”和“休闲”人员均可被临时调用。“值班”人员已有车辆绑定，只有人员和车辆都无冲突时才能立即承接新任务；正在作业的人员不可同时执行另一工单。
3. 临时调用“休闲”人员时，调度员选择一辆尚未被其他值班人员占用且可用的加油车，确认人员到岗后将其转为“值班”并建立车辆绑定。若无可用车辆，应提示资源不足，人员保持“休闲”，不得生成工单。
4. 状态和车辆绑定保存后，调度台、该人员的工作台以及可用调度资源及时同步。智能调度只使用已启用、处于“值班”、车辆绑定有效且满足车辆状态与油量约束的人员和车辆；“休闲”人员只能经调度员临时调用后参与派工。
5. 同一人员同一时刻只能负责一辆车；同一车辆同一时刻只能对应一名值班人员。重复调用或绑定应提示冲突。

### FR-05 调度人员调整休闲/休息状态及移出队伍

1. 调度人员可将无活动工单的“值班”人员改为“休闲”，解除车辆绑定，让其继续候命；也可将“值班”或“休闲”人员改为“休息”，移出可调度队伍。调整时记录原因（例如交班、请假、临时离岗）。状态变更不删除账号、人员资料或历史工单。
2. 人员或负责车辆存在“作业中”工单时，不允许直接转为“休闲”或“休息”；界面提示先完成作业或按现有异常流程处理。
3. 存在“待执行”工单时，调度人员必须先将工单改派给其他可派工的值班人员/车辆，或按业务规则撤销工单；状态和车辆绑定变更应在检查通过后一次性生效。
4. “休息”人员不再收到临时调用或新工单；“休闲”人员可再次被临时调用，但在转为“值班”前不能直接派工。人员工作台仍可登录查看本人状态和无任务提示；车辆实际状态仍按车辆业务规则维护。
5. “休息”结束后，调度员确认人员已可候命，才可将其调整为“休闲”；不得通过派工操作隐式跳过此步骤。

### FR-06 人员与车辆、工单的一致性

1. 调度台展示的“负责人员”以当前有效“值班”绑定为准；历史工单保留派发时的人员和车辆信息，不随交班覆盖。
2. 新工单或人工改派必须同时满足：账号启用、人员处于“值班”、车辆绑定有效、车辆可用且油量足够，并且人员无并行作业冲突。服务端在保存时重新校验，防止多个调度员同时操作造成冲突。
3. 加油人员仅能查看及上报明确分配给本人的工单。人员换车、转为“休闲/休息”或账号停用后，不得通过旧会话继续操作不属于自己的工单。
4. 人员创建、停用、重置密码、三态切换、临时调用、车辆绑定变更均记录操作者、时间、对象、变更前后状态、原因和操作结果，供交接班追溯。

## 5. 页面与交互

- **管理员工作台**：在现有“航班导入、现场情况播报”之外增加“人员与账号管理”。包含人员列表、创建/编辑弹窗、重置密码及停用/启用操作。创建成功时展示一次性初始密码交付提示。
- **调度人员工作台**：在现有“加油车资源”附近增加“人员与可调度资源”，以状态标签展示“值班、休闲、休息”，并提供“设为休闲”“临时调用”“安排休息”“更换车辆”；操作前展示相关车辆和工单的影响，操作后立即刷新态势与工单。
- **加油人员工作台**：显示本人工作状态和负责车辆；处于“休闲”时显示候命说明，处于“休息”时显示不可派工说明。已有工单状态上报流程保持不变。
- **登录页**：继续使用统一账号密码入口，根据服务端返回的角色自动进入对应工作台。首次登录修改初始密码应在进入业务页面前完成。

## 6. 验收场景

1. 管理员创建调度账号后，新账号能登录调度台；其他角色不能调用创建账号接口。
2. 管理员创建加油人员账号后，调度台 5 秒内显示新人员，初始状态为“休息”；该人员可登录，但看不到可执行工单。
3. 调度人员确认人员结束休息后将其设为“休闲”；该人员出现在可临时调用名单中，但智能调度不会直接给其派工。
4. 调度人员临时调用“休闲”人员并绑定空闲车辆后，状态转为“值班”；后续新工单可分配给该车辆，该人员能在本人工作台看到工单。
5. “值班”人员及车辆空闲时可被临时调用；若已有作业中工单，系统拒绝同时派发另一项立即执行的任务。
6. 同一人员或车辆被重复调用/绑定时，系统拒绝第二次操作并说明冲突。
7. 有待执行或作业中工单的人员不能直接转为“休闲”或“休息”；处理工单后才可变更。转为“休息”后，临时调用和智能调度均不得选择该人员。
8. 管理员停用人员账号后，该账号不能登录，已有会话不能继续请求接口；历史工单仍可追溯。
9. 加油人员尝试访问其他人员工单或提交状态，服务端拒绝；调度人员尝试创建账号，服务端拒绝。
10. 两名调度人员同时操作同一人员/车辆时，最终只产生一条有效车辆绑定，另一方收到明确冲突提示。

## 7. 与当前代码的衔接及已确认口径

当前 `users` 表仅有账号、明文密码、角色和 `vehicle_id`；`vehicles.driver` 是姓名文本；工单只关联车辆。实现本需求需要独立的人员工作状态与车辆绑定关系、工单人员归属和操作记录，并迁移现有演示账号与车辆数据。现有登录、调度优化、人工改派、司机工单接口都需要同步校验三态与人员归属。

**已确认的业务口径**：调度员的“添加和减少加油人员”指调整可调度队伍，不创建或删除登录账号。账号始终由系统管理员管理。调度员可临时调用“值班”和“休闲”人员；“休息”人员不可临时调用。
