# 网站流程说明书实施与验收

实施日期：2026-11-03。依据：[网站流程审查与修改说明书](https://chatgpt.com/space/page_961cbb010e3c8191a57c478d7cf43fb5)。沿用 React/MUI、Python 标准库 HTTP 服务和 SQLite。

## 已实施的业务规则

| 条目 | 修改后的行为 |
| --- | --- |
| M1 加注实绩 | 正常完成必须达到本单计划量。零加注或部分加注须填写原因，记录实际量、扣除实际油量，进入差额待确认，保留车辆。调度确认现场情况后释放原车，仅安排剩余需求。 |
| M2 资源一致性 | 取消待执行工单或航班会释放资源；异常工单终止后不能重开。作业中及差额待确认的航班不能以取消/离港事件跳过交接。晚到事件不会重开已完成航班。 |
| M3 航班编辑与导入 | 两种入口共享校验；必须使用带时区的有效日期，禁止直接改变已有活动工单或实际加注记录的需油量。导入先逐行预览，确认时再次校验，只写入有效行。 |
| M4 初始密码 | 服务端强制首次改密；改密后重新读取账号状态并发新会话，撤销旧会话。首次改密期间会话撤销可恢复普通登录。 |
| M5 人员字段 | 创建、修改和查询只返回允许公开的人员字段，不返回密码哈希。 |
| M6 会话 | 退出撤销服务端当前会话；改密撤销该用户旧会话；无效会话返回 401，网页清理本地会话并回到登录页。 |
| M7 时间可信度 | 按用户确认：预计到达加 18 分钟作业，须离港前完成，提前缓冲为 0。不可行时显示风险；按时保障率显示暂无数据。新建示例使用相对日期，已有数据日期原样保留，过期无活动工单计划归入历史。 |
| M8 风险生命周期 | 确认只记录确认人、时间和说明，风险继续存在且保持原 ID；实际资源、差额或时间条件解除后自动归档。 |
| M9 错误反馈 | 弹窗校验及服务端错误保留在操作位置，五秒轮询不清除；成功、关闭或重新打开时按操作状态更新。 |
| M10 工作台 | 当前任务优先；支持工单搜索、历史查看，以及航班号、机位、状态、日期筛选；窄屏固定快捷导航；风险可定位到相关工单或资源。 |
| M11 地图与候选 | 简化默认标签，点击查看详情，可展开地图并显示状态图例；临时分配列出候选和车辆被排除的具体原因。 |

此前实现的移除“现场情况播报”、安排补油、临时分配人车和示意位置推荐继续保留。实际执行中的人员与车辆不允许直接跳过交接更换。

## 验收证据

测试运行生产 HTTP 入口和隔离 SQLite 数据库。最终 25/25 项通过（6.091 秒）：原有 12 个场景保留，新增 13 项；新增场景在修改前版本验证失败，再在修改后验证通过。测试清单、日志、浏览器截图和迁移结果存放于工作区的 `outputs/airline-spec-implementation/tests/` 与 `outputs/airline-spec-verification/`。

浏览器已走通：计划 8,400 L → 先加 100 L → 待调度确认且原车保留 → 确认后生成 8,300 L 新工单 → 足量完成，累计 8,400 L，车辆从 12,100 L 降至 3,700 L。还验证了零输入取消、导入预览与拒绝行、跨轮询保留错误、风险确认后仍活动、候选排除原因、地图展开、900 像素调度页及 390 像素司机页。

管理员与认证浏览器检查包括表单建号、首次改密、两次密码不一致、旧会话撤销后跳转、首次改密期间再次撤销后的恢复；共 6 项通过。测试账号仅位于本地隔离库，验收后停用。

旧版本业务库升级检查 12 项通过；真实生产数据库复制件升级检查 39 项通过，包括已有字段、油量、任务状态保持不变与重复启动幂等。原副本不被测试修改。旧任务没有实际加注记录时显示“未记录”，不推断历史足量完成。

## 改动规模与复核

相对本轮开始时记录 SHA 的源码，业务后端净增 262 行，前端净增 270 行；原有补油/临时分配工作不计为本轮新增。增加的代码主要用于实际加注与差额持久化、共享校验、风险生命周期和提交后响应；前端从调度页提取了地图及航班列表组件。没有新增依赖或服务层。逐文件明细在 `work/airline-spec-implementation/change-size.json`。

复核范围是本轮修改的 `backend/app/server.py`、认证与登录、管理员和司机页面、调度页面及两个提取组件、Header/通知、两处未用导入清理和对应 HTTP 测试。业务代理、前端代理、独立测试代理和主代理进行了分工复核；未将这次复核表述为整个仓库审计。

## 发布与边界

后端使用新版本目录及原子符号链接切换，数据库保持 `/var/lib/airline-app/dispatch.db`。停服后用 SQLite backup API 生成一致备份；验证失败时停止服务，再同时恢复旧代码和旧数据库。Cloudflare Pages 静态页面经原有 Worker 访问 HTTPS 后端。

已发布到 https://airline-ashyh.pages.dev/ 。版本目录为 `20261103-spec-0dcf83d20cfb`，Cloudflare 部署 ID 为 `57a51c3d-d6bd-45ea-bc3e-8febc623188a`。公网三种角色工作台均返回 200，退出后的旧会话均返回 401；公网 HTML 与本次构建 SHA256 一致。

首次发布检查发现响应早于事务提交，紧接退出的请求仍可短暂通过。检查触发自动回滚，原服务恢复；修复统一 POST 提交与响应顺序后才重新发布。该场景纳入可控制提交延迟/失败的 HTTP 回归。

位置、路程、到达时间和 18 分钟作业时长仍为演示模型，未接入真实机场 GPS 或保障 SLA。通过率表示已覆盖场景通过，不能换算为网站整体准确率、生产并发能力或真实机场调度效果。本轮源码、部署版本及验收证据可通过 Git 提交与部署文件哈希核对。
