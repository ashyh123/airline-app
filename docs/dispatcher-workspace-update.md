# 调度工作台调整记录

日期：2026-11-03。来源：调度工作台网页体验反馈。

## 本次需求

1. 移除页面下方的「现场情况播报」，同时移除导航入口和人工发布接口。右上角继续显示系统生成的风险、工单和补油通知。
2. 对油量不足以满足航班保障需求的可用车辆，调度员可以安排补油。补油入口不能只在低于容量 20% 时出现。
3. 支持待执行工单临时分配、换车和换人；按机坪位置推荐就近且油量合格的人员与车辆组合。

## 实现约定

- 复用现有 React 工作台、Python API、SQLite 和工单状态，不更换项目框架。
- 补油分为调度员「安排补油」和负责司机「确认补油完成」。安排后车辆进入补油中，暂不参与航班派工；确认完成后才恢复满油并重新调度。补油操作写入审计。
- 所有已绑定值班司机、未满油、无活动工单且状态可用的车辆都可以安排补油。界面列出当前不满足的待保障航班，便于调度员判断。
- 人工分配只操作待执行工单。服务端重新校验车辆状态、油量、人员状态和任务冲突，在一次事务中完成绑定、工单转交、旧资源释放、预计到达时间重算和人工锁定。
- 休闲且账号启用的人员可以在分配时临时调用；休息、停用人员不参与推荐。正在作业的工单继续走既有作业上报和异常流程。
- 已值班人员可以带着待执行工单更换空闲车辆，作业中不允许直接换车。

## 示意位置

沿用现有航班、机位与车辆的 `x/y` 坐标，航站楼在上、机坪在中、跑道在下。西侧补油点设在 `(1,17)`，未绑定车辆的人员统一在人员候命区 `(3,17)`；绑定人员随车辆显示位置。

这些是可用于演示调度的机坪示意位置，不是真实机场地图、GPS 或实时定位。候选按「人员到车 + 车辆到机位」的示意距离排序，界面使用示意单位并明确预计到达时间为估算。派单不把当前位置提前改成目标机位；开始作业时才更新到位位置。

## 验收场景

- 网页不再出现人工现场播报表单和导航。
- 类似 JF-08 的 3,900 / 12,000 L 车辆，即使高于 20% 安全阈值，仍有安排补油入口。
- 补油中油量不增加、不能被派给航班；完成确认后才补满并恢复调度。
- 临时分配展示人员、车号、油量、示意位置、距离与预计到达，按距离排序，允许人工选择。
- 换车、临时调用及换人后，工单归属、车辆占用、人员绑定和司机工作台一致；候选失效时整体拒绝，不遗留一半成功的绑定。
- 自动调度、人工分配和补油均由服务端执行约束检查；司机只能确认自己负责车辆的补油完成，不能安排补油或操作其他车辆。

## 设计检查

本次将补油与临时分配的约束放到服务端，覆盖所有页面入口；调度员只选择候选，油量、距离和资格由系统计算。复用现有坐标与人员候命点，避免引入地图供应商、定位设备或新任务系统。新增的补油状态和候选接口分别服务于补油过程与原子分配，现有单步补满和纯车辆改派无法表达这两个过程。

验证：12 个生产 HTTP 路径回归场景全部通过，覆盖并发争用、过期候选、司机归属与权限；旧版本在两阶段补油场景下明确失败。生产构建通过；浏览器验证了 JF-08 补油、人员带待执行工单换车与旧车释放。全仓 lint 仍有 3 个原有未使用变量错误，已用 Git 原版逐个复现；本次没有新增 lint 错误。详细证据位于同级输出目录 `airline-dispatch-verification`。CLI Agent 与原生测试的对比实验尚未开展；本次新增的回归测试属于这次功能变更，不能算作仓库原先已有的测试。
