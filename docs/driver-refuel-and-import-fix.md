# 司机确认补油与航班导入修复（2026-11-07）

调度员安排补油；仅该车当前值班司机可在司机工作台确认已补满。调度员、管理员和其他车辆司机不能代确认。无负责司机的车辆须先绑定司机；允许为低油车辆绑定司机以执行补油，油量阈值仍阻止航班派工。补油期间不能停用、解绑或更换负责司机。

导入实测发现：原 CSV 解析直接按逗号切分，保留了标准 CSV 的引号，导致合法时间和需油量被后端拒绝。新解析支持带引号字段、转义引号、字段内逗号/换行、UTF-8 BOM；列数不符和重复表头报错，不再静默截断。JSON BOM 可导入，格式或非数组错误有中文提示。Excel xlsx 需另存 CSV UTF-8。

过去离港时间允许导入历史计划，预览与结果明确标注；历史数据不会自动派工，需通过历史筛选查看。

验证：25 项真实 HTTP 回归，4 项文件解析测试，生产构建及相关 ESLint；本地浏览器完成调度安排→司机确认→满油恢复，以及带引号 CSV 预览→应用（含历史计划提示）。未用真实业务数据作写入测试。


## 司机主动申请补油（2026-11-07）

值班且绑定车辆的司机可在司机工作台填写 4–500 字原因，并选填现场剩余油量（0 至车辆容量的整数）。上报油量仅供调度参考，不覆盖系统油量，也不改变车辆状态、位置或现有工单。

调度工作台显示待处理申请和已安排申请。调度可安排补油，或填写原因退回；司机可看到结果并在退回后重新申请。有待执行、作业中或差额待确认工单时，不能安排补油，须先处理作业或交接。安排后仍由负责该车的司机确认补满。

每辆车最多一条待处理或已安排申请；数据库唯一索引和串行事务共同避免重复。换车、换班、停用或替换司机时取消原司机待处理申请；补油中的车辆仍不可解除绑定。申请、处理和完成均有操作记录。

新增 `refuel_requests` 表，原业务表和数据保留。接口：司机 `POST /api/driver/refuel-requests`（reason、可选 reportedFuel），调度 `POST /api/refuel-requests/{id}/resolve`（action=approve/reject，退回须 reason）。司机工作台只返回本人的最近申请；调度 overview 返回所有待处理和已安排申请。

验证：真实 HTTP 覆盖全流程、工单不变、错误角色、油量校验、退回重提、交接取消、并发重复申请；原有回归保持通过。
