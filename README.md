# 机场加油车智能调度系统

这是根据《机场加油车调度子系统软件需求规格说明书》与《人员账号、工作状态与临时调用管理需求》实现的可运行原型。它围绕“航班数据导入 / 事件接入 → 智能调度 → 人工微调 → 工单执行 → 异常预警 → 现场播报”的闭环设计，并在此之上提供人员账号、三态工作状态与临时调用的完整管理能力，适合课程设计演示、后续工程化迭代和接口联调。

## 已实现的业务能力

- 三角色登录与权限隔离：调度人员、加油人员、系统管理员分别进入独立工作台；接口同时校验角色与用户身份。
- 人员与账号管理：管理员可创建调度员、加油员账号（工号唯一、初始密码一次性展示、首次登录强制改密），编辑资料、重置密码、停用 / 启用账号；账号停用后其会话立即失效。
- 密码安全：密码以 PBKDF2-SHA256 哈希存储，旧明文自动迁移；接口永不返回明文密码。
- 三态工作状态：加油员处于值班 / 休闲 / 休息三态之一。值班→休闲 / 休息须无活动工单并填写原因；休息状态不能自行恢复值班。
- 临时调用：调度员可将休闲状态的加油员临时调回值班——选择一辆可用且未被占用的加油车，确认后人员转为值班并建立车辆绑定；值班中可更换车辆。
- 派工归属校验：智能调度只给“值班 + 账号启用 + 绑定有效车辆”的司机派工；人工转派校验目标车有值班司机；开始作业校验账号与值班状态。
- 操作审计：人员创建、密码重置、状态流转、临时调用、账号停用 / 启用均写入操作日志（操作者、时间、对象、前后状态、原因、结果）。
- 航班数据导入：调度人员可批量导入或按航班号更新航班计划，支持 UTF-8 的 CSV 与 JSON 两种格式。
- 现场情况播报：调度人员可发布普通 / 需关注 / 紧急三个级别的现场播报，出现在右上角“运行通知”中，可关联具体航班。
- A-OCS 航班事件接口：支持落地、延误、取消和离港；使用 `eventId` 去重，避免重复消息造成重复派工。
- 智能分配：基于航班优先级、加油车可用状态、剩余油量和机坪示意距离的可解释启发式分配。
- 人机协同：调度员可将工单改派给合格车辆，并将这项决定锁定，不会被后续自动调度覆盖。
- 加油作业执行：待执行 → 作业中 → 已完成的合法状态流转；完成作业时必须提交车辆当前油量，系统据此更新车辆剩余油量并恢复可用状态；异常必须填写原因，车辆自动转维修并生成风险告警。
- 指挥态势：俯视风格的机坪态势图（航站楼、机位、滑行道、跑道、车辆位置）、车辆油量、活动工单、风险列表、利用率、按时保障率和当班人员状态。
- 安全边界：油量不足、不可用车辆、非法状态流转、非法事件、越权访问、停用账号和重复绑定车辆均会返回明确错误，不会静默处理。

## 角色工作台

| 角色 | 可用功能 |
| --- | --- |
| 调度人员 | 查看全场态势、生成智能方案、人工改派和锁定工单、处置风险预警、导入航班数据、发布现场播报；管理当班人员：查看三态分布、办理值班 / 休闲 / 休息流转（须填原因）、临时调用（绑车转值班）、更换车辆。不能代替司机提交作业状态。 |
| 加油人员 | 查看本人工作状态横幅（值班 / 休闲 / 休息 + 负责车辆与油量）与待办、进行中工单；可上报开始、完成（须提交当前油量）和带原因的异常。休息或非值班状态下不会收到新工单。 |
| 系统管理员 | 人员与账号管理：创建调度员 / 加油员账号并分配角色权限、编辑资料、重置密码、停用 / 启用账号，以及查看操作审计所需的接口数据。 |

演示登录页采用账号密码，不让使用者选择角色；系统根据账号权限自动进入工作台。演示账号为 `dispatch01 / dispatch123`、`driver01~driver03 / driver123`、`admin01 / admin123`。管理员新建的账号会获得一次性初始密码（仅创建时展示一次），首次登录强制修改。实际部署时应接入机场统一身份认证、会话过期和网关令牌校验。

## 界面说明

- 调度工作台采用“左侧功能指引 + 分区内容”的布局：功能指引提供态势总览、机坪态势、风险预警、任务时间轴、作业工单、资源与指标、当班人员、航班导入、现场播报九个分区的快速定位。
- 「当班人员」分区每 5 秒自动刷新：状态筛选、调度员与司机一览（工号、姓名、账号状态、工作状态、负责车辆、当前任务），行内按钮随状态变化——休闲可临时调用 / 安排休息，值班可设为休闲 / 更换车辆，休息可设为休闲。
- 机坪态势图为 SVG 俯视示意：草地、水泥机坪、T1 航站楼与登机口、滑行道、跑道（含编号与中线）及航班停机位；红色飞机为高优先级航班，车标颜色表示车辆状态（绿：可用，蓝：已预留/作业中，灰：维修中）。
- 司机端顶部显示三态状态横幅与负责车辆实时油量；不符合派工条件时明确提示“暂无可执行工单”。
- 顶栏右上角提供运行通知（播报、风险、工单动态）与退出登录；退出后清空会话并返回登录页。

## 架构

```text
A-OCS / 模拟事件 ──POST /api/events──> 调度服务
航班导入（CSV/JSON）──POST /api/admin/flights/import──> ┤
现场播报 ──POST /api/admin/broadcasts──>               ├─ SQLite（航班、车辆、工单、告警、播报、事件去重、人员与审计）
调度指挥台 / 司机端 <──JSON API─────────────────────────┤
                                                       └─ Scheduler（当前：启发式；生产：OR-Tools 可替换）
```

主要接口（除登录外均需 `Authorization: Bearer <token>`）：

| 方法与路径 | 角色 | 说明 |
| --- | --- | --- |
| `POST /api/auth/login` | 公开 | 账号密码登录，返回用户信息与令牌 |
| `POST /api/auth/change-password` | 登录用户 | 修改密码；首次登录（`must_change`）强制修改 |
| `GET /api/overview` | 调度 | 全场态势（统计、工单、车辆、航班、告警、播报、人员与三态计数） |
| `POST /api/dispatch/optimize` | 调度 | 生成 / 更新智能调度方案 |
| `POST /api/tasks/{id}/override` | 调度 | 人工微调并锁定工单（目标车须有值班司机） |
| `GET /api/alerts/{id}/recommendations`、`POST /api/alerts/{id}/resolve` | 调度 | 风险处置建议与归档 |
| `GET /api/admin/flights`、`POST /api/admin/flights/import` | 调度 | 航班查询与批量导入（路径保留 `/admin` 前缀，权限已归调度员） |
| `POST /api/admin/broadcasts` | 调度 | 发布现场情况播报 |
| `POST /api/events` | 调度 | A-OCS 航班事件接入（幂等） |
| `GET /api/admin/personnel`、`POST /api/admin/personnel` | 管理员 | 人员列表（角色 / 状态 / 搜索过滤）与创建（生成初始密码） |
| `POST /api/admin/personnel/{id}/profile` | 管理员 | 编辑姓名 / 电话 |
| `POST /api/admin/personnel/{id}/reset-password` | 管理员 | 重置密码，新密码仅返回一次并删除该用户会话 |
| `POST /api/admin/personnel/{id}/disable`、`.../enable` | 管理员 | 停用（有活动工单时拒绝）/ 启用账号；停用即失效会话 |
| `POST /api/dispatch/personnel/{id}/status` | 调度 | 值班→休闲 / 休息（须无活动工单并填原因；休息不能直接转值班） |
| `POST /api/dispatch/personnel/{id}/call` | 调度 | 临时调用：为休闲人员绑定可用车辆并转值班 |
| `POST /api/dispatch/personnel/{id}/vehicle` | 调度 | 值班人员更换绑定车辆 |
| `GET /api/driver/tasks`、`POST /api/tasks/{id}/progress` | 司机 | 本人工单查询与进度上报（完成须带 `fuelLevel`；返回含本人工作状态） |

## 运行

前提：Python 3.11+、Node.js 20+。后端零第三方依赖；前端可用 npm 或 Yarn 安装依赖。

```bash
# 终端一：启动后端（零第三方依赖）
cd backend
python -m app.server

# 终端二：启动 React 调度台
cd frontend
npm install        # 或 corepack yarn install
npm run dev        # 或 npm start，默认 http://localhost:3000
```

打开前端地址后，使用演示账号登录。以调度员身份点击“生成调度方案”即可为待保障航班分配合格车辆；可导入航班数据、发布播报、微调工单、管理当班人员；以管理员身份可创建新人员账号并体验首次登录强制改密；再登录司机账号模拟开始 / 完成（提交当前油量）/ 异常上报，回到调度台查看态势与告警闭环。

默认数据库是 `backend/dispatch.db`，首次启动会写入演示数据（含演示账号、车辆与人员初始状态）。要重置演示环境，停止服务后删除该单一文件再启动即可。

## A-OCS 事件示例

```json
POST /api/events
{
  "eventId": "aocs-20260914-0001",
  "flightId": "f1",
  "type": "ARRIVED"
}
```

合法 `type`：`ARRIVED`、`DELAYED`、`CANCELLED`、`DEPARTING`。返回中包含本次增量调度结果和最新态势数据。

## 生产演进建议

当前 `Scheduler` 保持了清晰的替换边界，适合在真实机坪数据接入后迁移到 OR-Tools 的 VRPTW 模型：将时间窗、加油量、车辆容积、车辆故障、行驶时间矩阵及人工锁定作为约束，设置短时间上限生成近优解。`backend/requirements-production.txt` 列出了 FastAPI、Uvicorn 与 OR-Tools 的生产依赖建议；演示服务选择标准库，以保证下载即能运行。

部署前还应补充：接入机场统一身份认证（替代本地口令）、HTTPS、消息队列与失败重试、审计日志的归档与查询界面、设备离线缓存、监控告警，以及对接真实 A-OCS 的协议适配器。人员与账号模块当前以 SQLite 存储密码哈希和操作日志，生产环境应将口令迁移到专用凭证服务并限制审计日志的访问范围。

前端基于 [Mantis Free React Material UI Dashboard Template](https://github.com/codedthemes/mantis-free-react-admin-template) 的 Vite 结构、主题与通用布局进行二次开发；该项目为 MIT License，原许可证保留在 `frontend/LICENSE`。

生产调度建议采用 [Google OR-Tools](https://github.com/google/or-tools) 的车辆路径求解能力（Apache-2.0）；本原型的 `Scheduler` 接口已为此预留替换位置。没有直接复制 OR-Tools 代码。
